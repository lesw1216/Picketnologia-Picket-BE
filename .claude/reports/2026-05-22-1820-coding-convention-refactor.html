6. 알려진 제약 · 주의사항 · Follow-up

UsernameNotFoundException 유지: CustomUserDetailsService.loadUserByUsername은 Spring Security의 UserDetailsService 계약이 해당 예외 타입을 던지도록 요구하므로 BaseException 규칙에서 의도적으로 제외. Javadoc에 사유 명시.
Spring 쿼리 바인딩 동작 확인: Product 계열 Request DTO 3종에서 @Setter를 제거했다. 컴파일은 통과하나, 컨트롤러가 query parameter를 POJO로 바인딩((ProductQueryRequest q))할 때 Spring DataBinder가 setter를 사용하는 경향이 있으므로 staging 머지 후 swagger UI로 실제 query 바인딩이 정상 동작하는지 검증이 필요. 문제가 있을 경우 후속 조치 옵션: (a) @Setter 복원 + 규칙 문서에 예외 명시, (b) Controller에서 @RequestParam으로 개별 수신 후 빌더로 변환.
BaseResponse 래핑 신규 적용 엔드포인트: POST /reviews/register, GET /seller/test, POST /qna/qna_create_post, DELETE /qna/{id}, DELETE /rounds/{id}/seats 등은 응답 JSON 구조가 변경됨 (이전에는 raw string 또는 단일 객체). 프론트엔드에서 response.result / response.isSuccess 패턴으로 처리되는지 확인 필요.
사전 테스트 실패 2건:
  • PicketApplicationTests.contextLoads() — DB 연결 (DriverDataSource) 실패. test profile 구성 부재가 원인. 본 PR 범위 외.
  • ReservationServiceTest.register() — Mockito UnnecessaryStubbingException. test 코드 정리 필요. 본 PR 범위 외.
이들 실패는 staging branch에서도 동일하게 발생함을 확인.
BaseException 시그니처: 기존 BaseException(message, status) 2-arg 생성자도 존재하지만 본 작업에서는 통일성을 위해 BaseException.from(status) 정적 팩토리만 사용. 메시지는 BaseResponseStatus enum의 message가 그대로 사용된다.
